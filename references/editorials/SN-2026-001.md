# 程式碼變便宜之後，難的是驗證：Nadella 談 software factory 與動手做

Microsoft 執行長 Satya Nadella 上 Gergely Orosz 主持的 The Pragmatic Engineer，談當程式碼生成變便宜、驗證反而變難時，軟體工程會變成什麼樣子。官方標題〈Software engineering after code becomes cheap with Satya Nadella〉，官方節目頁日期為 2026 年 11 月 16 日，全長約 63 分。官方頁註記本集在 Redmond 錄製。本文是 Celebrities 的導讀與評論，不是節目官方中文版，也與 Microsoft、The Pragmatic Engineer 沒有合作關係。

## 01｜模型一跳躍，使用形態就要改（05:55–09:52）

談到 GitHub Copilot 一度領先、後來又要追 Cursor 與 Claude Code，節目頁筆記整理他的體會是：模型出現非線性的跳躍時，使用模型的形態可能很快改變。本站轉述大意：做 AI-first 產品，得預期下一個模型會改寫使用方式，對已經做好的東西不能太戀棧。約 07:09 起。

編輯解讀：這段把「被超車」收成一條可重用的產品原則：先不要保護舊形態，先假設下一個模型會改寫使用方式。

## 02｜decision engines，以及軟體工程還活著（09:52–12:32）

他對 decision engines 很興奮，認為那是可嵌入、可重複呼叫、比較節省 token 的新 primitive，不必每次都讓模型重新生成。「我認為，這正是軟體工程依然非常有生命力的地方之一。」（I think that this is one of those places where software engineering remains very much alive.，據 The Pragmatic Engineer 節目頁筆記）10:20 起。同一段稍後，他還把 decision engines 比成智慧時代的 stored procedure。

編輯解讀：重點不是再讚美一次大型語言模型，而是他在找「生成之後還能留下來的工程元件」。

## 03｜code 變便宜之後，難的是驗證（約 11:50；官方章節 12:32 起再展開）

進入 software factory 時，程式碼生成變便宜之後，難處轉到驗證（本站轉述大意）。約 11:50 起。後續談到 software factory、規格與驗證迴圈的重要性（本站轉述大意）。官方章節 The software factory 從 15:39 起再展開。

編輯解讀：這個看法是本集的主軸；後面的工廠、規格、brownfield 是同一條線的展開，而不是另一個題目。

## 04｜從工程師走來：以前工具鏈很穩，這次不一樣（24:06–26:29）

被問到導入人工智慧為何不像改用 React 那樣時，他回顧自己從 Sun 到 Microsoft 的工程師經歷（本站轉述大意：過去很長一段時間，寫程式的工具環境相對穩定）。節目頁筆記整理他看到的差別是：這一次改變的不只是單一技術，runtime、framework 和 IDE 的概念都在變，新模型推出時也可能讓既有做法失效。約 24:20 起。

編輯解讀：這是少數能同時看見「工程師出身」與「這波變革有多深」的段落；重點是對照，不是懷舊。

## 05｜掌握自己的基礎設施：harness 要和模型分開（45:39–51:21）

談企業為何要自己掌握人工智慧基礎設施時，節目頁筆記整理他的建議是：讓 harness、memory 與模型彼此不綁死，才能輕鬆替換模型，避免被單一模型供應商鎖定；也要建立自己的私有 eval，用來決定該採用、升級哪個模型。約 49:59 起。

編輯解讀：這和庫內既有「各家模型都可以用，但要保有獨立於各家的能力」是同一方向，但這次把方法說得更具體：分開 harness，並且用自己的 eval 當檢驗標準。

## 06｜少說多做，就是現在（59:26–結尾）

收束時，他希望連自己都能提高動手的比重：「如果我能改變自己『說』與『做』的比例，我會。就是現在這個時候。」（If I could change the ratio of my “talk” to “do,” I would. This is the time.，據 The Pragmatic Engineer 節目頁筆記）59:43 起。

編輯解讀：這句的力度來自身分：一個必須大量對外說明的執行長，仍然把「做」放在「說」前面。

## 中文短摘要

Microsoft 執行長 Satya Nadella 上 The Pragmatic Engineer，主張程式碼生成變便宜之後，軟體工程的難處轉到驗證，團隊要打造 software factory。他回顧自己從 Sun 到 Microsoft、長年在 IDE 裡寫程式的穩定工具鏈，對照這一波連使用形態都可能被新模型改寫；並提出 harness 要和模型分開、用私有 eval 檢驗能否替換模型。給工程師的建議是：現在就把「說」換成「做」。
